Composable, path-aware JSON/YAML mappings, configurable diagnostics, and
constexpr reflection checks. C++11 and later.

## Breaking changes and migration

JSON/YAML names are in `omni::ryml` unless qualified.

| Previous API | Replacement |
| --- | --- |
| `settings` | `config_t<>` |
| `.settings` | `.config` |
| `map_tree` / `map_tree_t` | `map_by_schema` / `map_by_schema_t<>` |
| `.transform_settings(f)` | `.tdm_config(f)` |
| `with_diagnostics<T, D>` | `with_diagnostics_t<T, D>` |
| `diagnostics<true>` / `diagnostics<false>` | `diagnostics` |
| `.map_value(f)` | `.transform(f)` |
| `.map_error(f)` / `.transform_error(f)` | `.transform_diagnostics(f)` |
| `render_diagnostics(d)` | `render_diagnostics(tree, d)` |
| `fn::is_static<T>` | `fn::is_static_t<T>` |
| `fn::non_static<T>` | `fn::is_non_static_t<T>` |
| `fn::compile_time_predicate<P>` | `fn::compile_time_predicate_t<P>` |

- **Callable entry points:** unbound `core::deserialize` and `core::map_tree`
  are replaced by the `deserialize` and `map_by_schema` callable objects.
  Configure them through `.tdm_config` or construct their `_t` types with
  `.config`. Tree builders move from `core::` to the `ryml::as_owning_tree`
  and `ryml::as_ref_tree` callable objects.
- **Shared defaults:** callable objects have one identity across translation
  units. C++11/14 expose references to shared storage;
  use `std::decay<decltype(object)>::type` to name callable types. Pointers
  to these reference-exposed defaults cannot be template arguments before
  C++17. C++17+ use inline objects.
- **State first:** read callbacks take `(state, node, type<T>)` or
  `(state, node, T*)`; write callbacks take `(state, value) -> NodeRef`.
  Writers obtain their destination with `state.node()`; `state.at(node)`
  selects another node in the same builder-owned tree.
  Forward state to nested mappings. Accept a generic `State`, constrained by
  `is_read_state` or `is_write_state`: paths, containing types, and local
  selectors change the state specialization. Root-state construction is
  private; callbacks receive copyable states and can derive children.
- **Value mappings preferred:** pointer calls are fallbacks for unavailable
  value production or assignment, never retries after mapping errors.
- **Diagnostics:** `deserialize` returns rendered text by default; configure
  its transformation for another result type. `map_by_schema` borrows the
  caller's tree; temporary trees are rejected. Keep tree and character storage
  alive for borrowed values and diagnostics. `deserialize` exposes no tree.
  Collection of multiple errors (`error_limit > 0`) is experimental.
- **Removed:** `diagnostics::tree`, `issue::value`, `offset`, `line`, `column`,
  and `diagnostics::stopped()`. Rendering takes the tree explicitly; traversal
  states enforce limits. `parse_message` becomes `parse_error_message`.
- **Recovery removed:** missing required fields are errors, including fields
  with declaration initializers. Absent optionals remain supported; other
  recovery requires custom mappings.
- **Strict scalar kinds:** quoted numbers need custom conversion for numeric
  destinations. Shape errors report expected/found kinds.
- **Predicates:** use `fn::filter(fn::is_static)` or
  `fn::filter(fn::is_non_static)`; the trait form
  `fn::filter<fn::is_static_t>()` remains valid.
- **C++11 enum entries:** pair-like rather than exactly `std::pair`.
- **Instrumentation:** reflection-dependent headers require the generated
  header force-included (`-include` or `/FI`); `omni_reflected_target` handles
  this. `functional.hpp`, `compat.hpp`, and `traits.hpp` remain independent.

## JSON/YAML mapping

- Global `cp::to_type` / `cp::from_type` registrations, including nested lookup.
  Use variable templates from C++14 or `_t` struct specializations in C++11;
  register only one form per type and direction.
  Registered callables must be copy-constructible; configured tuples need not
  be trivially copyable.
- Public mappings name their inputs: `map_object_node` reads an object;
  `map_record` writes a record. Node readers check shape by default and expose
  `.with_node_check` / `.tdm_with_node_check` for already validated input.
  Callback compositors use `compose::map_<shape>_node`; enum callbacks use
  `compose::map_string_node`.
- `ryml/map_node.hpp` and `ryml/map_type.hpp` group mappings by direction;
  `ryml/customization.hpp` provides registration and selection. `ryml.hpp`
  remains sufficient.
- `core::parse_as_*<T>(node)` converts validated values without mapping state,
  returning `expected<T, issue>`. `parse_as_boolean(node)` returns
  `expected<bool, issue>`. Checked node mappings apply diagnostic policy.
- `serialize` defaults to JSON; `tdm_format` selects the output format while
  preserving local mapping selection. `as_json` and `as_yaml` remain available.
- Local `map_node` selectors override global mappings through `.tdm_map_node`
  or designated initialization, in both traversal directions. Defaults retain
  `cp::to_type` / `cp::from_type` selection.
- Read traversal is limited to tree depth 10. Child transitions return a
  terminal sentinel at the limit, preventing further path/type instantiation;
  mapping the sentinel reports a depth-limit error. Writes currently stop
  silently at the same boundary, pending diagnostic-aware serialization.
  Records with several recursive fields can still require excessive
  compilation time and compiler memory.
- Read/write states expose constexpr `path()`, `enclosing_record` (parent),
  and `enclosing_root` (original root). Paths use C++ field names, with `[]`
  for container values: `root.offices[].number`. Aliases and runtime keys or
  indices do not affect them; recursive schema edges reuse their first path.
  Path-aware selectors take state by value for C++17/20 constant evaluation.
- Shape compositors check nodes before custom conversion. Callbacks support
  `expected` with one issue or an issue range, or `with_diagnostics_t`.
  Value callbacks can also provide mutating assignment adapters.
- Defaults cover records, enums, char-based strings, Booleans, integers,
  `float`/`double`, optionals, sequences, sets, and string-keyed maps.
  Shared operation traits support custom strings, nullable types, and
  containers.
  Multimaps retain repeated keys; unique containers follow duplicate policies.
- Existing-object overloads support roots without default constructors.
  Ranges replace existing contents; errors leave destination state unspecified.
- Field setters support value mappings, including bitfields. Pointer mappings
  support nonassignable fields; custom value mappings can construct
  non-default-constructible elements in ranges and optionals.
- `config_t` transforms diagnostics while the parsed tree lives.
  `ryml/with_diagnostics.hpp` provides `with_diagnostics_t` with
  `transform`, `and_then`, `or_else`, and
  `transform_diagnostics`, retaining reports through sequencing.
- Shared `mapping::record_strategy` configures field filtering, aliases,
  field validation, and record finalization. `mapping::enum_strategy` configures
  enum aliases. Both support `tdm_` updates; JSON/YAML mappings bind them with
  `tdm_strategy`. Strategy families expose `is_record_strategy` and
  `is_enum_strategy` traits, `_v` values, and C++20 `_like` concepts.
  Static fields can be serialized explicitly; deserialization excludes them.
  Field validators also check omitted optionals; typed string keys support
  generic callbacks. Nested validation follows diagnostic limits and early
  stopping.
- Canonical record names win even with invalid values. Tuple-based alias
  dictionaries expose checks for existing names and disjoint aliases.
- `ryml/core.hpp`: metadata-independent parsing, node checks, and conversions.
  Raw conversions require validated input; checked defaults validate it.

## Reflection and functional utilities

- C++11 constexpr `reflected_call` and `fn::instrumented_validation`.
- Callable metadata predicates with `_t<T>` traits; `&&` / `||` short-circuit
  instantiation. Added non-functional/assignable predicates and
  `always_true` / `always_false`.
- `fn::try_fold`: expected-like accumulator with early failure return.
- `fn::lookup_table`: constexpr named-metadata lookup with typed dispatch and
  expected-like chaining.
- `omni::cpp11_static_string` and C++20 `omni::nttp_string`: compile-time
  strings with search, comparison, and concatenation. `OMNI_META_STRING`
  provides literal tokens across supported standards.
- C++11 constexpr enum pairs through `compat::pair`.
- `OMNI_CONSTRAINED_TEMPLATE`: C++20 constraints with earlier-standard SFINAE.
  `_REDECL` supports redeclarations without repeating default arguments.

**Warning:** constexpr `reflected_call` is only for isolated `static_assert`
checks. Instrumentation substitutes placeholder results; using them for types,
template arguments, array sizes, or `if constexpr` can produce different code
in instrumentation and final compilation. Checks defaulting to false need an
instrumentation-aware validation adapter.

## Fixes

- Avoid Windows command-line limits when forcing reflection regeneration.
- Avoid repeated AST scans for type completeness during instrumentation.
- Preserve copy-only values and avoid invalid nonassignable-field assignments.
- Enforce diagnostic budgets; retain document paths and borrowed issue ranges.
  Render accumulated nested parse-error text once per report.
- Use unsigned-byte ordering for fallback string views, including UTF-8 names.
- Support optional emplacement without exceptions and C++11 constexpr
  construction in the compatibility backend.

## Guides and integration

- Expanded JSON/YAML guide: defaults, configuration, diagnostics, and nested
  customization. Target renamed `guide.json` → `json_ryml.guide`.
- JSON/YAML Codespaces sandbox with printed success/error examples and guarded
  C++11/C++20 syntax.
- Single-executable directories use `main.cpp`; guides/examples have standalone
  CMake setup, separate from test standard matrices.
- [Codebase conventions]: naming, customization, composition, layout, and
  guides.
- Extension dependencies remain opt-in through CMake components.
- Release preparation waits for matching commit CI and propagates failures.
