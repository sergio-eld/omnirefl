This release expands member reflection and JSON/YAML mapping, with breaking API changes listed below. The public interfaces remain compatible with C++11 and later.

## Reflection

- Reflect accessible static data members and non-overloaded static member functions alongside non-static members. New `is_static()` queries and `omni::fn::is_static` / `omni::fn::non_static` predicates let visitors select either category.
- Bindings now expose their corresponding metadata interface, including record queries such as `is_union()` and `is_template()`. Use `as_meta()` to select the unbound metadata accessors when a binding has a same-named accessor.
- Add record queries `is_union()` and `is_template()`, and data-member queries `is_bitfield()` and `bit_width()`. Template-dependent bitfield widths remain unsupported; the width accessor is omitted with a warning.
- Add experimental metadata exclusion through `omni::tweaks::skip_metadata<Types...>` and the namespace-scope convenience macro `OMNI_SKIP_METADATA(...)`. Requests apply throughout the translation unit. Skipped types retain supported dependency-discovery protocols but cannot be immediate `reflected_call` arguments. A template specialization selects its primary template.
- Data members representing `omni::function_t` expose `has_callable_metadata()` and `callable_metadata()` for accessing the associated function metadata.

## JSON/YAML serialization

- Replace the templated strategy with concrete `settings`. Customize a callable through `transform_settings`, or pass settings explicitly to the functions in `omni::ryml::core`.
- Configure duplicate-field selection, unknown-field handling, error and warning limits, and recovery of missing fields using exposed defaults or value initialization where supported. Invalid values are errors rather than candidates for missing-field recovery.
- Mapping consistently returns `with_diagnostics`: a valid value can accompany warnings; failures retain diagnostics without exposing a partially initialized value. Diagnostics remain lazy and can be adapted through `transform_diagnostics`.
- Deserialize scalar and vector document roots, including nested vectors and vectors of reflected records.
- Serialize empty optionals as null at the document root or in record members. Empty optional sequence elements are omitted; remaining elements retain their order.
- Expose `core::as_owning_tree` and `core::as_ref_tree` for inspecting or editing a RapidYAML tree before emission. The owning builder copies string storage; the borrowed builder requires that storage to remain alive and unchanged and rejects temporary inputs.

## Fixes

- Fix false incomplete-type errors in valid template and lambda call chains, including calls through `std::apply`.
- Discover dependencies from deduced member-function return types. Unsupported return-type dependencies receive more specific warnings where possible.
- Preserve inherited public alias discovery through metadata-skipped types.
- Correct `const` and `volatile` data-member queries across primary-template specializations.
- Fix C++14 constant-predicate use with `omni::fn::branch` and `omni::fn::when`.
- Remove the experimental indexed-reflection path that could cause instrumentation stack overflow on large translation units.

## Breaking changes and migration

| Previous API | Replacement |
| --- | --- |
| `public_fields()` / `public_fields_t` | `accessible_data_members()` / `accessible_data_members_t` |
| `public_methods()` / `public_methods_t` | `accessible_member_functions()` / `accessible_member_functions_t` |
| `field_meta_t` / `field_binding_t` | `data_member_meta_t` / `data_member_binding_t` |
| `field_meta` / `field_binding` concepts | `data_member_meta` / `data_member_binding` |
| `OMNI_FUNCTION_TAG(...)` | `OMNI_FUNCTION(...)` |
| Serialization `strategy` and builder methods | `settings` and `transform_settings` |
| `map_diagnostics(...)` | `transform_diagnostics(...)` |
| `omni::ryml::parse(...)` | `omni::ryml::core::parse(...)` |

- `index()` is removed from data-member metadata and bindings.
- Experimental indexed reflection, `OMNI_ENABLE_INDEX_MODE`, the CMake `ENABLE_INDEX_MODE` option, and `omnirefl/unique_id.hpp` are removed.
- Accessible-member queries now include static members. Existing visitors intended to process object state should filter for non-static members. The serialization extension does this by default.
- JSON/YAML mapping no longer selects between `expected` and `with_diagnostics` based on the strategy type. Update callers to inspect the returned `.value` and `.diagnostics`.
- Mapping policies and diagnostic enums are shared under `omni::json`. Existing policy configuration must be migrated to the new settings structure.

## Guides

The core comprehensive guide is reorganized into navigable, executable Basics and Advanced sections. Sneak Peek now demonstrates metadata queries and member access directly. The serialization example is replaced by an executable JSON/YAML guide, available through the `guide.json` build target and CTest entry.
